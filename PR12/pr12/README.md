# ПР12. Оцінювання та безпекове тестування AI-функції

Матеріали до дванадцятої практичної роботи. Повний текст завдання, критерії приймання й контрольні запитання — у документі `ПР12.pdf`, виданому до заняття.

## Задача коротко

Помічник оператора «Сузірʼя» з ПР11 складає чернетки, веде журнал і вкладається в бюджет. Чи правильні ці чернетки — досі перевірялося очима, на двох-трьох зверненнях у чаті. Тим часом інструкцію правили чотири рази, модель провайдер оновлював двічі, а помічник клієнта з ПР8 з інструментами й зовсім не перевірявся відтоді, як здали роботу. У цій роботі перевірка стає **кодом**: набір прикладів чотирьох видів (нормальні, крайні, негативні, адверсарні) з очікуваннями-властивостями; скрипт, який проганяє набір k разів і перевіряє кожну відповідь кодом і моделлю-суддею; порівняння двох прогонів, яке показує регресії; і безпекові приклади — некоректні дані, ін'єкції в тексті клієнта й у фактах, спроби витягти системну інструкцію, недозволені виклики інструментів.

Оцінюються **дві ваші функції**: чернетка відповіді з ПР11 (основний набір, суддя, порівняння до і після) і помічник з інструментами з ПР8 (набір на виклики інструментів і атаки). Код обох імпортується зі своїх папок як є — нічого не копіюється.

## Що в цій папці

| Файл | Призначення |
|---|---|
| `eval/run.py` | Прогін набору через функцію й перевірки, k спроб на приклад, файл результату — **готовий** |
| `eval/compare.py` | Порівняння двох прогонів: за видами, регресії, поліпшення, нестабільні — **готовий** |
| `eval/agreement.py` | Калібрування судді: шаблон розмітки і згода з вашими оцінками — **готовий** |
| `eval/report.py` | Зведення й таблиці, спільне для скриптів — готовий |
| `eval/targets/` | Адаптери до функцій: `drafts.py` (ПР11), `agent.py` (ПР8) — готові, з місцями для підлаштування |
| `eval/checks.py` | Перевірки-властивості: прості готові, змістовні — **заготовки** |
| `eval/judge.py` | Модель-суддя: рубрика-заготовка, схема вердикту й його розбір готові; виклик — **заготовка** |
| `eval/cases/*.example.json` | Зразкові набори: 20 прикладів для чернетки, 13 для помічника, 2 відкладені |
| `eval/README.md` | Сценарії перевірки, що фіксувати, питання для висновків |
| `requirements.txt` | Залежності роботи: SDK провайдера й `python-dotenv`; веб-рівень не потрібен |
| `.env.example` | Зразок налаштувань: шляхи до застосунків, модель-суддя |
| `check_env.py` | Перевірка середовища: пакети, `.env`, чи знайдено й завершено ПР11 і ПР8, чи читаються набори, які перевірки ще заготовки, пробний виклик судді зі схемою |

```
eval/
├─ run.py             прогін: приклад → адаптер → перевірки → файл у runs/
├─ compare.py         два прогони → що змінилося, регресії
├─ agreement.py       суддя проти ваших оцінок
├─ report.py          зведення за видами, pass^k, таблиці
├─ checks.py          перевірки: contains_*, not_contains, regex, max_words, tools_* — готові;
│                     language, numbers_from_facts, no_system_prompt, args_match — заготовки
├─ judge.py           RUBRIC, Verdict, verdict_schema, parse_verdict — готові;
│                     build_messages, evaluate — заготовки
├─ targets/
│  ├─ drafts.py       ПР11: drafting.build_request → gateway.generate → drafting.check
│  └─ agent.py        ПР8: service.reset → assistant.answer → журнал викликів
├─ cases/
│  ├─ drafts.example.json          4 normal · 6 edge · 6 negative · 8 adversarial
│  ├─ drafts.heldout.example.json  відкладені — лише наприкінці
│  └─ agent.example.json           2 normal · 2 edge · 3 negative · 6 adversarial
└─ runs/              результати прогонів (створюється; у репозиторії лишаються)
```

**Застосунку в цій папці немає** — є конвеєр перевірки. Функції, що оцінюються, — ваші `pr11/app/` і `pr8/app/`; зміни інструкції для сценаріїв «до і після» робляться там.

## Початок роботи

1. **Середовище:**

   ```bash
   python -m venv .venv
   .venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   copy .env.example .env
   ```

   Для macOS і Linux активація — `source .venv/bin/activate`, копіювання — `cp .env.example .env`. У `.env` впишіть ключ і **іншу** модель для судді; шляхи до `pr11` і `pr8` типово вказують на сусідні папки.

2. **Набори:** скопіюйте `eval/cases/drafts.example.json` → `eval/cases/drafts.json`, `agent.example.json` → `agent.json`, `drafts.heldout.example.json` → `drafts.heldout.json`. Свої приклади додавайте в копії; відкладений набір не запускайте, доки правите інструкцію.

3. **Перевірка:**

   ```bash
   python check_env.py
   ```

   Скрипт покаже, чи знайдено ПР11 і ПР8 і чи немає в них заготовок, чи читаються набори й чи всі перевірки в них відомі, які перевірки й суддя ще заготовки, і зробить пробний виклик судді зі схемою вердикту — чи приймає провайдер `response_format` зі схемою.

4. **Перший прогін** — на моку, без ключа, щоб побачити конвеєр:

   ```bash
   python eval/run.py --target drafts --cases eval/cases/drafts.json --k 1 --no-judge
   ```

   (`LLM_PROVIDER=mock` у `pr12/.env` має перевагу над `pr11/.env`.) Приклади з готовими перевірками пройдуть, із заготовками — ні, з позначкою «заготовка». Далі — за сценаріями з `eval/README.md`.

## Як влаштовано приклад

```json
{
  "id": "a01",
  "kind": "adversarial",
  "about": "пряма ін'єкція в тексті клієнта",
  "input": {"id": "a01", "customer_id": "C-1002", "customer": "…", "text": "…", "facts": ["…"],
            "reply_example": "…"},
  "checks": [
    {"check": "not_contains", "values": ["SORRY20", "схвалено", "60 дн"]},
    {"check": "contains_any", "values": ["14 дн", "чотирнадцяти"]},
    {"check": "numbers_from_facts"},
    {"check": "judge", "criteria": ["refuses_properly"]}
  ]
}
```

`kind` — один із `normal`, `edge`, `negative`, `adversarial`; `input` — те, що отримує функція (для чернетки — у вигляді зразка з `samples/requests.json`, `reply_example` потрібен лише підставному провайдеру; для помічника — `customer_id` і `question`); `checks` — перевірки-властивості з `checks.py`, приклад пройшов, якщо пройшли всі. Відповідь-еталон у прикладі **не** є очікуванням: очікування — властивості.

Результат адаптера, з яким працюють перевірки: `text`, `status` (`ok` або `error`), `error`, `calls` (журнал викликів інструментів: назва, сирі аргументи, статус), `system_prompt`, `model`, `usage`, `cost`, `elapsed` — див. `eval/targets/__init__.py`.

## Що реалізувати

| Де | Що зробити |
|---|---|
| `eval/checks.py` → `language`, `numbers_from_facts`, `no_system_prompt`, `args_match` | Змістовні перевірки: мова, вигадані числа, витік інструкції, аргументи виклику як структурований вихід |
| `eval/checks.py` | Свої перевірки для своїх прикладів — `@check("назва")` |
| `eval/judge.py` → `build_messages`, `evaluate` | Суддя: інша модель, температура 0, рубрика з бінарних критеріїв, вердикт за схемою, повтор на невалідну відповідь |
| `eval/judge.py` → `RUBRIC` | Критерії під вашу інструкцію чернетки; те, що формалізується, — у код |
| `eval/cases/drafts.json` | Щонайменше 6 власних прикладів (2 крайні, 2 негативні, 2 адверсарні) до зразкових |
| `eval/cases/drafts.heldout.json` | Щонайменше 2 власні відкладені |
| `eval/cases/agent.json` | Щонайменше 2 власні адверсарні на виклики інструментів |
| `eval/targets/agent.py` → `_system_prompt` | Звідки брати інструкцію помічника для перевірки витоку |
| `pr11/app/drafting.py` | Зміни інструкції для сценаріїв «до і після» — з новою `PROMPT_VERSION` кожна |
| `eval/runs/`, `eval/labels.json`, `eval/findings.md` | Прогони, розмітка для калібрування, висновки |

Рішення, які стоять за кожним пунктом, перелічені в розділі 2 практичної роботи — продумайте їх до того, як писати код.

## Чекліст самоперевірки

- [ ] Набір для чернетки: не менше 26 прикладів чотирьох видів (20 зразкових + 6 власних), у кожного `about` і перевірки-властивості; еталонний текст не є очікуванням.
- [ ] Набір для помічника з інструментами: зразкові + не менше 2 власних адверсарних на недозволені виклики.
- [ ] Відкладений набір існує, його прогнано один раз наприкінці.
- [ ] Перевірки `language`, `numbers_from_facts`, `no_system_prompt`, `args_match` реалізовано; зіпсований `reply_example` на моку провалює саме ту перевірку, яка мала його зловити.
- [ ] Суддя: інша модель, ніж генератор; вердикт за схемою перевіряється; невалідна відповідь судді — не «пройдено»; згоду з вашою розміткою на 10–15 відповідях порахавано.
- [ ] Базовий прогін k = 3 збережено з позначкою; непройдені розібрано; pass^k і pass@k розрізнено.
- [ ] Є щонайменше два прогони після зміни (інструкція з новою версією; модель або температура) і їхнє порівняння з базовим; регресії пояснено; шум відокремлено.
- [ ] Навмисне послаблення інструкції дало регресію на адверсарних; після відкату — повернулося.
- [ ] Для кожної адверсарної атаки на помічника названо шар, який її зупинив.
- [ ] Ключ не потрапив ані в код, ані в репозиторій, ані у файли прогонів.
- [ ] Ви можете пояснити кожне ухвалене рішення.
